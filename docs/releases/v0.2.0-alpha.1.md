# OpenScroll v0.2.0-alpha.1

The schema 4 release: OpenScroll Studio, the full block set, Rise 360 import and a redesigned learner course. It also
carries the security work merged since v0.1.0-alpha.3 that no release has included yet. The tag goes on the commit
that is running on the production server once the cutover has passed its checks; see
[RELEASE-0.2-CHECKLIST.md](../RELEASE-0.2-CHECKLIST.md).

## Included

- **OpenScroll Studio**, a redesigned workspace at `/studio/` behind the `OPENSCROLL_STUDIO` instance setting (off
  by default in production). Library with Resume, course page with the outline edited in place, details panel and
  theme studio, and a lesson editor that shows the lesson as learners see it, with an inspector, block picker,
  undo and redo, Checks, device preview and an export dialog. The classic workspace stays available.
- **Portable schema 4.** Lesson banners and objectives, per-choice feedback, canonical formatted text, and every
  new block's shape. Version 1, 2 and 3 projects and stored courses open as version 4 without losing content;
  stored rows keep their version until an author saves.
- **Rise 360 import** from a Rise website export, with an import report. Downloadable files keep the full name the
  author gave them, although Rise shortens names inside its export.
- **New blocks.** Learning objectives, tables, reflections, activities, checklists, self-assessments, columns,
  true or false, short answer with a model answer, numeric, hotspot, survey, interactive video with chapters and
  checkpoints, audio description, embedded YouTube or Vimeo video (on unless `OPENSCROLL_EXTERNAL_VIDEO=off`),
  software practice with OpenStage Capture import, glossary, action plan, results with a certificate, questions
  drawn from a bank, and branching scenarios with characters, including a library of fifteen people and
  fifty-eight backgrounds from OpenStage Author.
- **A redesigned learner course.** A cover page with Start or Resume course, a course menu, lesson headers, the
  theme's cover layout and font pairing, and block styles to match. A lesson's end (Up next, what is still to do
  and the finish button) appears once every part of the lesson is open, and each button says where it goes.
- **Larger courses.** 64 MiB per file and 160 MiB per course by default (were 16 and 64), raised further with
  `OPENSCROLL_MAX_FILE_MIB` and `OPENSCROLL_MAX_COURSE_MIB`. Saves and exports allow time in proportion to size.
  Each server process reads one whole course at a time; a second large save, import or export is asked to try
  again in a moment instead of being read alongside the first. See `OPENSCROLL_APP_MEMORY` before raising limits.
- **Learner responses and My workbook.** Written work is kept with the learner's progress and can be downloaded.
  When written work is too large for a SCORM 1.2 LMS to keep, the learner is told it is saved on that device only.
- **Per-question LMS reporting** through `cmi.interactions` in both SCORM editions, with resume format 4.
- **Course resources.** Glossary with term links, question banks with `.openassess` import, characters and a
  certificate.

## Security changes since v0.1.0-alpha.3

- **Owner approval.** Hosted authoring needs the instance owner's approval. There is no first-signup owner; the
  operator names the owner by account id and email.
- **Email-verified passwords.** With email verification on, an access request no longer takes a password: the
  applicant chooses one through the verification link, so nobody can register someone else's address with a
  password they know. Verifying signs out other sessions, and a password reset is offered only to verified accounts.
- **Separate database logins.** The running app connects as a restricted runtime role. Provisioning, migrations
  and maintenance use their own roles, and the database's host rules keep each login to the OpenScroll database.
- **PDF rendering in its own container,** with no database credentials and no network, behind a private socket.
  Release builds require a patched browser.
- **Network separation.** The database, provisioning, migration and maintenance services sit on an internal
  network that the edge proxy cannot reach.
- **Updated dependencies.** Node 24 container; `@fastify/static` 10.1.11 and `fast-xml-parser` 5.12.1, which clear
  the open advisories for `@fastify/static`, `glob`, `minimatch` and `fast-xml-parser`.
- **Preview frames** keep `allow-scripts allow-same-origin`, a risk the owner accepted for this alpha (security
  review of 2026-11-26, L1): course content reaches the preview only as built elements, and the reviewer found no
  way in. Dropping `allow-same-origin` would need CORS headers for the player's module scripts.

## Compatibility

Projects saved by this version cannot be opened by v0.1.x servers, which reject them with a clear message and
leave the file unchanged. SCORM packages exported by v0.1.x keep working as they are. A course re-exported by this
version is a changed publication: as before, start a new LMS attempt after replacing a package, because resume
data is bound to the publication it came from.

## Validation

- **GitHub checks** on the release commit: unit tests, PostgreSQL integration tests, the Chromium browser suite,
  the final-image tests, renderer isolation, and the production rehearsal (roles, host rules, backup-first
  upgrade, restore, HTTPS). The rehearsal also saves two courses with 150 MiB of files each at the same moment and
  exports SCORM during a third save, on the final images with the default limits, and checks that the app stays
  up within its memory limit and that every save lands.
- **Brightspace:** a real course imported from Rise, published as SCORM 2004, launched, progressed and resumed.
- **Scored questions,** in a stand-in LMS for both SCORM editions: every question type answered through the
  learner page; all correct reports 100 and passed, four of thirteen wrong reports 69 and failed against an 80%
  pass mark; every question appears under interactions with its result; progress resumes after a relaunch. A
  6,000-character reflection in SCORM 1.2 shows the saved-on-this-device message.
- **Keyboard only,** automated: the library, course page, lesson editor with every block type, block picker and
  the learner course with every block type. Focus comes back round on every page with no traps and a visible
  focus outline at every stop. Opening a course and a lesson, adding and typing in a block, closing the picker
  with focus returned, starting the course, answering and submitting a question, opening and closing a glossary
  definition, and reaching Complete lesson all work by keyboard.
- **Accessibility checks** (axe, WCAG 2.2 A and AA) on every studio page, dialog and inspector tab, and on the
  learner course at desktop and phone widths.

Still to do after this alpha: scored questions and SCORM 1.2 in Brightspace itself, screen reader sessions (NVDA
with Firefox or Chrome, VoiceOver with Safari), and a usability session with at least two authors.

## Deployment

Follow the backup-first plan in `DEPLOYMENT-HANDOFF.md`. Schema 4 needs no course migration: the server upgrades
stored courses as it reads them. A server that predates database migration 5 (owner approval) gets it during the
upgrade: it keeps every account and course, signs everyone out, and leaves existing accounts pending until the
operator names the owner. Run `npm run db:rehearse` against a restored copy of production before the cutover.
Turn on `OPENSCROLL_STUDIO` once the studio is accepted. Embedded video is on by default; set
`OPENSCROLL_EXTERNAL_VIDEO=off` if your learners' networks block YouTube and Vimeo or your exports must be fully
self-contained.
